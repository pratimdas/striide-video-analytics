# Local lab implementation rules

- This pack is the specification. Do not change production Striide code or deploy externally.
- Never print .env contents, expose provider keys to the browser or embed secrets/signed URLs in telemetry or reports.
- Video paths are approved local inputs; expose job-owned media IDs to tools, not arbitrary filesystem paths.
- Gemini must receive actual visual evidence for inspection. Pegasus JSON alone is not independent visual verification.
- No context is a supported first-class input. Do not infer age, identity, intent, pain, nutrition or psychological state.
- Sport recognition is provisional until sufficient evidence; conflicts trigger bounded inspection or needs_context.
- Ontology fields are definitions, not proof that detectors or expert approvals exist. Keep the original file immutable.
- No numeric pose metrics without an implemented validated measurement source. No score/radar when inputs or rubric approval are absent.
- Unknown is not a failed skill. Single-attempt clips cannot establish repeatability.
- Code Mode tools enforce path scope, schemas, budgets and read-only ontology access in the host. Generated code cannot replace score or publication rules.
- Do not run generated code through host eval, new Function or node:vm as a claimed sandbox. Use the restricted executor and permission-denial tests.
- Use British English and current StriideAi assets. No fabricated claims, provider timing, telemetry or benchmark outcomes.
- Keep offline fixtures visibly labelled; network and live API checks must have distinct results.
- Raw artifacts are internal. Athlete HTML/PDF/JSON exports must not include diagnostics, filesystem paths or secrets.
